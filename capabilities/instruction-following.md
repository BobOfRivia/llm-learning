# Instruction Following

> 桥接：Agent 项目 dimensions/05-instruction-following.md

## 当前水位（截至 2026-05）

指令遵循能力已经从"核心能力"演变为"基础设施"——用户不再把它当作能力来称赞，只会在它出错时注意到。这个状态本身就是能力成熟度的标志。

**基础 IFEval**（Google，2023，可程序化验证的精确指令：长度限制、必须包含某个词、特定格式等）上，头部模型普遍在 85-90%+ 区间：Scale AI 排行榜（2024 年数据点）显示 Gemini 2.0 Flash Experimental 约 86.6%、Claude 3.5 Sonnet 约 86.0%、GPT-4o 约 85.3%。2026 年前沿模型（Claude Mythos Preview、GPT-5.4、Claude Opus 4.6）在此基础上继续提高，差距主要缩小在细节失误上。

**IFBENCH**（2025 年）是这个能力真正的当前边界：它引入了更多样、更难的可验证约束组合，GPT-4.1 和 Claude 3.7 Sonnet 这一代在 IFBENCH 上得分均低于 50%。这个数字揭示了一件重要的事：单条指令遵循已经接近饱和，**多约束叠加场景**（同时满足格式要求 + 长度限制 + 角色扮演 + 内容边界 + 输出结构）仍然是可靠的失误来源。

benchmark 生态在 2025 年扩展出多个维度：**M-IFEval**（多语言版本）、**LIFBENCH**（长上下文指令稳定性，测试在长文档中能否保持指令约束不漂移）、**MM-IFEval**（多模态，涉及图像时的约束遵循）、**IFEval-FC**（function calling 中的格式约束），每个维度都揭示了不同场景下的具体失误模式。

一个定性判断：复杂指令遵循的失误大多不来自"理解错了指令"，而来自"长上下文中指令被遗忘"（尤其是早期出现在 system prompt 中的约束在长对话后漂移）或"多条约束互相冲突时的优先级处理错误"。这两类失误的技术来源不同，解法也不同。

## 技术归因

指令遵循能力的根本驱动力是**训练信号质量，不是规模**。这是和 reasoning 能力最重要的区别——1.3B InstructGPT 优于 175B GPT-3 的实验结果，直接定义了这条轨道的价值所在。

**训练轨道阶段 2（SFT + RLHF）是直接来源**（→ [训练范式 - 阶段 2](../tracks/training.md)）。InstructGPT 的三步流水线（SFT 习得格式、RM 捕捉偏好、PPO 优化）是"从语言模型到助手"这个质变的核心机制。这个阶段的 SFT 数据质量决定了指令遵循能力的覆盖范围——哪些指令类型可以被可靠遵循，直接取决于 SFT 数据中是否有充分的示范。

**训练轨道阶段 3（DPO）提升了稳定性**（→ [训练范式 - 阶段 3](../tracks/training.md)）。DPO 相比 PPO 的一个实践优势在于：它可以更精细地从偏好数据中学习细粒度的约束遵循质量——"回答格式更符合要求"、"边界情况下不漂移"这类细节，在 DPO 的偏好对训练中可以更稳定地被捕获。开源社区从 DPO 获益尤为明显：DPO 实现的低复杂度使得指令遵循训练可以迭代更快。

**对齐轨道阶段 1-2 是同一组技术的对齐视角**（→ [对齐技术](../tracks/alignment.md)）。RLHF 和 DPO 既是"训练技术"，也是"对齐技术"——它们同时做两件事：使模型遵循用户指令，也使模型遵守安全边界。这两个目标在大多数情况下相互促进，在边界情况（有害指令）上产生张力。对齐训练在这条能力上的独特贡献是**系统提示词的权限模型**（operator vs user 分层）：2024 年以来，头部实验室开始在训练中区分不同来源指令的优先级，使"系统提示词设定的约束应当比用户消息更持久"这个规则成为模型的训练目标，而不只是 prompting 约定。

**数据工程决定能力的覆盖边界**（→ [数据工程](../tracks/data.md)）。合成 SFT 数据的优势在于覆盖范围可以被工程化扩展——可以系统性地生成"稀少但重要"的指令类型（例如多语言约束、跨段落格式要求、多角色切换），而人工撰写数据很难覆盖长尾。Evol-Instruct 等方法通过自动化的指令复杂化，专门提升了多约束叠加场景的覆盖密度。

## 演进轨迹

**2018-2021：续写引擎时代**

GPT-3 的基本范式是自回归补全——给定前缀，预测下一个 token。"遵循指令"不是训练目标，而是偶发的涌现行为。GPT-3 可以在 few-shot prompt 的示范下完成特定格式任务，但这依赖 prompt 工程，不是可靠的能力：同样的任务换一个 prompt 格式，结果可以天差地别。对于这个时期的模型，"指令遵循"和"正确续写"之间的边界是模糊的。

**2022：InstructGPT——从续写到遵循的质变**

InstructGPT（Ouyang et al., OpenAI，2022 年 3 月，[arXiv 2203.02155](https://arxiv.org/abs/2203.02155)）是这条演进轨迹的分水岭。它的核心实验结论不是"更大的模型更好地遵循指令"，而是"正确的训练信号使小模型大幅超过大模型"——1.3B InstructGPT 在人类评估中优于 175B GPT-3，这 100 倍的参数量差距被训练方式弥合。

这个结果确立了这条能力维度的基本逻辑：规模是能力的必要条件，但"有用性"（helpfulness）需要专门的后训练信号才能获得，不会从规模中自然涌现。

**2022-2023：ChatGPT 使指令遵循成为基础期望**

ChatGPT 的大规模部署（2022 年 11 月）把指令遵循从"研究进展"变成了"用户基础期望"。这个时期的关键变化不是能力本身有大幅提升，而是**用户认知基准线被重置**——一旦数亿用户开始用 ChatGPT 完成日常任务，"模型能可靠地遵循自然语言指令"就成为了最低标准，而不是令人惊叹的特性。

同期，Llama 1/2 + 指令微调（Alpaca、Vicuna 等）证明了开源路线的可行性：通过高质量 SFT 数据微调，开源模型可以快速获得基本的指令遵循能力，催生了开源助手模型的爆发。

**2023：DPO 提升稳定性，系统提示词成为工程工具**

DPO（Rafailov et al., 2023 年 5 月，[arXiv 2305.18290](https://arxiv.org/abs/2305.18290)）的工程简洁性使偏好对齐训练迭代更快，指令遵循的细粒度质量（格式一致性、约束遵循稳定性）随之提升。

同年，system prompt 从"技巧"变成"工程工具"：开发者开始依赖 system prompt 定义应用行为，这推动了头部实验室对"system prompt 约束持久性"的专项训练——模型需要在长对话中不忘记 system prompt 设定的约束，并且在 user 消息尝试覆盖时正确拒绝。

**2024：复杂约束遵循与权限模型**

这个时期的能力提升主要体现在两个维度。第一是**多约束叠加**的可靠性：structured output（OpenAI，2024 年 8 月）使 JSON 格式输出从"大约能做"变成"可程序化保证"，这是通过推理时的约束解码（constrained decoding）而非纯训练解决的，是训练和推理工程的协同。第二是**operator vs user 权限分层**（Anthropic Claude 3 系列正式化，2024 年）：operator 的 system prompt 约束优先于 user 消息，形成明确的层级——这是 B2B 场景下可靠部署 AI 应用的基础。

**2025-2026：benchmark 饱和，复杂约束成为新前沿**

基础 IFEval 接近饱和，IFBENCH 的出现把前沿标准拉高。benchmark 生态扩展（多语言、长上下文、多模态、function calling 格式约束）说明"指令遵循"不是一个单一技能，而是一个在不同场景下有不同失误模式的能力族群。2026 年前沿模型在 IFEval 领先的同时，IFBENCH 上仍有提升空间，这条轨道还没有真正收敛。
