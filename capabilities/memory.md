# Memory

> 桥接：Agent 项目 dimensions/06-memory.md

## 当前水位（截至 2026-05）

"记忆"在 LLM 语境里实际上指向三件不同的事，需要先分清楚再谈水位：

**参数记忆**（parametric memory）是模型权重中编码的知识——训练数据见过的事实、语言模式、推理能力，都以这种形式存在。它是静态的，训练结束就固定了，更新它需要重新训练或微调。

**上下文记忆**（in-context memory）是把信息放进 context window 中，让模型在单次对话内"记住"。本质上这就是长上下文能力——能力水位见 [long-context.md](../capabilities/long-context.md)，关键约束是窗口大小和"Lost in the Middle"效应。

**跨会话记忆**（cross-session memory）是对话结束后仍能保留、下次对话中自动可用的持久信息。这是三者中技术架构最不成熟、但应用价值最明确的部分，也是本文件的核心主轴。

截至 2026 年 5 月，跨会话记忆的能力水位可以这样概括：**基础设施层已经成熟，产品层正在标准化，模型权重层尚未有突破**。用户在主流平台上可以依赖跨会话记忆，但底层架构仍然是"外部存储 + 检索注入"，不是模型原生的能力。

**ChatGPT**（OpenAI）在 2025 年 4 月完成了最重要的一次升级：从"保存用户显式要求记住的片段"扩展为"自动引用所有历史对话"，每次对话开始时模型会检索相关的历史信息注入上下文。2025 年 6 月扩至免费用户。这是从"主动管理的笔记本"到"被动的长期上下文"的哲学转变，代价是用户对"模型知道我什么"的控制粒度降低。

**Claude**（Anthropic）选择了不同的路线：记忆通过工具显式调用，而非自动注入。2025 年 9 月推出面向付费用户（Pro/Max）的 Memory 功能，10 月正式普及；2026 年 4 月，Claude Managed Agents Memory 进入公开 Beta——记忆存为文件系统上的文件，开发者可通过 API 读写、在 Claude Console 中管理，支持版本回滚和内容删除。这条路线的优势是透明度和可控性：开发者确切知道记忆文件里有什么，可以编辑、审计、导出。

**第三方记忆基础设施**（Mem0 等）在 2025-2026 年进入生产成熟期。Mem0 支持 19 种向量存储后端，图谱记忆（graph memory）在 2026 年初从实验性进入生产级部署，与纯向量检索相比提升约 2% 的整体性能（通过关系路径推断跨实体关联）。相比将完整历史对话发给模型，记忆层的 token 成本节省约 90%，p95 延迟降低约 91%。SimpleMem（2026 年 2 月）在 LoCoMo 跨会话对话 benchmark 上比 Claude-Mem 高 64%，是目前已有公开数据的最佳单一实现。

benchmark 生态仍不成熟：LoCoMo 是少数针对跨会话记忆的系统性基准之一，但覆盖场景有限，行业尚未收敛到类似 IFEval 或 RULER 这样的标准评估框架。

## 技术归因

当前跨会话记忆的实现方式决定了它的技术依赖结构——不依赖任何专门的模型训练，而是外部工程的叠加：

**长上下文能力（→ [long-context.md](../capabilities/long-context.md)）是工作记忆的上限。** 这是三者中和模型架构最直接相关的部分。Flash Attention、GQA、RoPE 外推使 context window 从 2K 扩展到 1M+，工作记忆的容量随之扩大。但上下文记忆不等于跨会话记忆——窗口关闭，信息消失，这是 Transformer 架构的基本特性。

**推理优化（→ [推理优化 - KV Cache](../tracks/inference.md)）决定了长上下文记忆的成本可行性。** KV Cache 管理是超长上下文对话的实际瓶颈：如果把整个历史对话都放进上下文，内存成本会随对话轮数线性增长。第三方记忆层（Mem0 等）的 90% token 节省，本质上是用"选择性检索"替代"全量历史拼接"，是推理成本优化和记忆能力的结合点。

**没有专门的训练机制对应跨会话记忆。** 这是当前架构的根本特征——主流模型在预训练和后训练阶段都没有明确针对"跨会话持久化"能力的训练目标。记忆能力是外挂的，不是内生的。这和 reasoning（RL 训练）、instruction-following（SFT + RLHF）形成鲜明对比。

## 演进轨迹

**2020-2022：上下文窗口是硬墙**

这个时期的"记忆"能力等于"上下文长度"——GPT-3 2048 tokens，超出窗口的信息就消失了。长文档处理的标准工程方案是"分块 + 摘要再注入"，由外部代码完成，模型本身无任何跨会话状态。

**2023：RAG 建立外部记忆的工程范式**

向量数据库 + 检索的 RAG 架构（LangChain、LlamaIndex 在这年快速普及）使"无限历史检索"在工程上成为可能：把对话历史、文档、用户信息存进向量库，每次对话时检索最相关的片段注入上下文。这是第三方记忆基础设施的前身。

同年 10 月，**MemGPT**（arXiv [2310.08560](https://arxiv.org/abs/2310.08560)）作为研究原型提出了操作系统式的 LLM 记忆管理：主上下文（"内存"）+ 外部存储（"磁盘"），通过工具调用的方式让模型主动管理自己的记忆边界，决定什么放进上下文、什么存进外部、什么可以遗忘。这是后来 Claude Managed Agents Memory 的概念前驱。

**2024：产品层记忆起步**

OpenAI 于 2024 年初为 ChatGPT 推出"Memory"功能（付费用户），允许用户让模型记住特定事实（名字、偏好、工作方式）——这是一个轻量的"个人笔记本"，用户主动管理内容。同年，Anthropic 推出 Claude Projects，允许用户在项目内维持持久的上下文和文档，是跨会话记忆的早期产品化。这个时期，两家公司的实现都还相对轻量，记忆更多是用户主动维护的"便签"，而非系统性的跨会话状态管理。

**2025：记忆能力的主要成熟年**

这一年发生的变化最多。**2025 年 4 月**，ChatGPT Memory 完成重大升级：不再只记录用户显式要求保存的片段，而是自动引用所有历史对话，在每次对话开始时检索相关历史上下文——从"主动维护的笔记"升级为"被动的长期记忆"。2025 年 6 月扩至免费用户，标志着大规模用户开始体验真正的跨会话记忆。

**2025 年 9 月**，Anthropic 为 Claude 推出 Memory，10 月扩至 Pro/Max 用户。与 ChatGPT 的自动注入不同，Claude 选择显式工具调用——模型决定何时去查记忆，而不是每次对话都自动加载。这一哲学差异在用户体验和隐私控制上各有取舍。

Mem0 在这年完成基础设施成熟化，进入大量 AI Agent 应用的生产部署（LangGraph、CrewAI、AutoGen 均有深度集成）。

**2026：开发者 API 层与生产级架构稳定**

2026 年 4 月，Claude Managed Agents Memory 进入公开 Beta，是迄今为止最完整的"developer-grade"记忆 API：文件系统存储、API 读写、Console 可视化管理、版本控制。图谱记忆从实验进入生产（Mem0 等），SimpleMem 发布并在 LoCoMo benchmark 上取得领先结果。

记忆基础设施的架构已经标准化：向量存储（语义检索）+ 可选图谱（关系推断）+ 外部文件系统（显式管理）+ 上下文注入。但这套架构仍然是外挂的工程方案，不是模型原生能力。

## 关键张力

**外挂记忆 vs 模型原生记忆**。目前所有主流的跨会话记忆方案，本质上都是"在对话开始时把相关历史信息注入上下文"——记忆存在外部系统里，模型本身每次对话仍然从零开始。真正的"模型原生记忆"（类似人类长期记忆那样通过学习将经验编码进参数）在学术上有探索（如持续学习、元学习方向），但没有任何主流系统在这条路线上有成熟产品。这个区别在实践中是否重要，取决于应用场景：对于大多数用例，外挂记忆够用；但对于需要"模型真正从每次交互中学习"的场景，现有方案是一个本质上的替代品而非等价物。

**记忆的可靠性与幻觉风险**。检索式记忆注入引入了一种新型错误：模型可能错误地"记住"了从未发生过的对话，或把记忆片段和当前上下文错误拼接。这类错误在 RAG 系统中已有充分研究（检索错误 + 模型幻觉的叠加），在跨会话记忆场景下同样存在，且用户更难察觉——因为用户倾向于相信模型"记得"的事情是真实发生过的。
