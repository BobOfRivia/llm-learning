# RLVR、GRPO、DAPO

> deadline: 2026-05-30
> status: pending
> 覆盖 tasks: RLVR（Reinforcement Learning from Verifiable Reward）的设计、GRPO vs PPO、PRM vs ORM、DAPO 对 GRPO 的四项修正
> 桥接: tracks/training.md, topics/rl-for-reasoning.md

**核心问题**：奖励来源从 human preference 换成 verifiable reward 之后，整个 RL 栈被改写了哪些地方？而 GRPO 跑到生产规模时又暴露了哪些问题、DAPO 怎么修的？要能讲清三层：

1. **RLVR 的范式变化**：verifiable reward（数学题对错、代码通过测试）让奖励信号从"人类感知 + 偏好模型近似" 切换为"程序判定 + 二值/连续可验证"。这个切换避开了哪些 reward hacking 模式（谄媚、词汇优化、表面合理性）— 但也带来什么新问题（只能在可验证域起作用、奖励稀疏）。
2. **GRPO 的核心简化**：用组内相对分数（同 prompt 采 N 个回答互比）替代 value model（critic），省掉一个完整模型的显存和训练。代价是什么 — 在什么情况下这个简化的方差会失控。
3. **DAPO 的四项修正**（ByteDance/Tsinghua 2025，是 GRPO 在 long-CoT 场景的生产修正）：
   - **Clip-Higher**：放宽上界 clip，允许低概率 token 涨上来（解决 long-CoT 探索不足）
   - **Dynamic Sampling**：过滤掉 reward 全对/全错的 prompt batch（这些 batch 没梯度信号）
   - **Token-level Policy Gradient Loss**：从 sequence-level 改为 token-level，避免长序列被短序列稀释
   - **Overlong Reward Shaping**：对超长输出做软惩罚，避免训练后期"越想越长"
   要能讲清每一项修正具体在解决 GRPO 的哪个失败模式。

**额外要解释**：PRM vs ORM 的本质权衡 — 步骤奖励 dense 但标注昂贵、结果奖励 sparse 但天然可验证。Math-Shepherd 等自动化 PRM 是不是真解决了标注成本问题。

**判断主线**：从 RLHF（人类偏好 + PPO）→ RLVR（可验证奖励 + GRPO）→ DAPO（生产规模修正）这条线的核心驱动力是**奖励信号质量 + RL 算法的工程可行性**两条同时演化。看懂这条双线演化才不会把 GRPO 当成"新 PPO"。
