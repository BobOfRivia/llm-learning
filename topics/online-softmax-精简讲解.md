# Online Softmax —— 针对你疑问的精简版

## 你的疑问一：前面没用最大值算的中间值，难道不是错的？

**结论：不是错的，只是"还没完成"。**

第 `i` 步的 `dᵢ` 定义是相对"截至当前已知最大值 `mᵢ`"的：

```
dᵢ = Σⱼ₌₁ⁱ exp(xⱼ − mᵢ)
```

它对"已经看过的 i 个元素"完全正确，只是还没看到后面的元素 —— 这叫**信息不完整**，不叫错。

每当最大值更新（`m_old → m_new`），之前的累积值会被**立即整体修正**：

```
d_new = d_old × exp(m_old − m_new) + exp(x_new − m_new)
```

所以正确的心智模型是：

> 不是"留着旧 max，用的时候再算对"。
> 而是**始终滚动维护 `(m, d)` 这对状态**，每一步结束时它们就已经是"截至当前的正确值"。修正是**即时**的，不是延迟到使用时。

### 追踪 x = [3, 1, -2, 4] 中 x₁=3 这一项的命运

| 步骤 | 当前基准 m | x₁=3 此刻的贡献 | 说明 |
|---|---|---|---|
| i=1 | 3 | exp(3−3) = 1.000 | 相对基准 3 正确 |
| i=2 | 3 | 1.000 | 基准没变，不修正 |
| i=3 | 3 | 1.000 | 基准没变，不修正 |
| i=4 | **4** | 1.000 × **exp(3−4)** = **0.368** | 基准变了，自动补算 |

最后一行：x₁ 的贡献被修正成 `0.368`，正好等于"一开始就用最大值 4 算 x₁"应得的 `exp(3−4)`。
**修正确实发生了，只是发生在被需要的那一刻。**

## 你的疑问二：分子乘修正因子对，分母乘修正因子也对吗？

**结论：对，而且和分子是同一条恒等式 —— 因为分母就是"一堆分子项的和"。**

### 核心代数事实：常数可以提进/提出求和号（分配律）

设第 i 步分母（旧基准）：

```
d_old = Σⱼ₌₁ⁱ exp(xⱼ − m_old)
```

注意求和号里**每一项**用的都是同一个 `m_old`。乘上修正因子 `c = exp(m_old − m_new)`：

```
d_old × c
= [ Σⱼ exp(xⱼ − m_old) ] × c        ← c 不含 j，是常数
= Σⱼ [ exp(xⱼ − m_old) × c ]        ← 分配律：c 提进每一项
= Σⱼ exp(xⱼ − m_new)                ← 每项满足你已认可的分子恒等式
= d_want   ✓
```

### 真实数字验证（i=3 → i=4，m 从 3 变 4，修正因子 = exp(3−4) = 0.368）

`d₃ = exp(3−3) + exp(1−3) + exp(−2−3) = 1.000 + 0.135 + 0.007 = 1.142`

**方法 A（整体乘）：** `1.142 × 0.368 = 0.420`

**方法 B（拆开逐项修正再求和）：**

| 项（基准 m=3） | × 0.368 | = 项（基准 m=4） | 直接用 m=4 算 |
|---|---|---|---|
| exp(3−3)=1.000 | ×0.368 | 0.368 | exp(3−4)=0.368 ✓ |
| exp(1−3)=0.135 | ×0.368 | 0.050 | exp(1−4)=0.050 ✓ |
| exp(−2−3)=0.007 | ×0.368 | 0.002 | exp(−2−4)=0.002 ✓ |
| **求和** | | **0.420** | **0.420** |

方法 A = 方法 B = 0.420，**逐项精确，没有任何近似**。

> 分母不是一个需要单独证明的新东西。它就是分子结论**套了一个求和号**。
> 你已经接受"每个分子项乘修正因子能修对"，而分母里每一项恰好就是这些分子项。

---

## 为什么这件事如此重要

因为修正因子能"提公因子"一次性作用于整个和，online softmax 只需存 **`d` 一个标量**，不需要保存所有历史项。

这正是 **FlashAttention** 能 work 的根本：K/V 被切成 tile 逐块处理，每块算完就用同一个修正因子把已累积的 `(d, O)` 整体对齐到新 max，无需把所有 K/V 读进显存才能求全局 max —— 从而避免标准 attention 的 O(N²) 中间矩阵反复读写 HBM。
